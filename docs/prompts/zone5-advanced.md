# 核心教学领域

## 1. Go Runtime 源码分析

### 1.1 调度器源码（runtime/proc.go）
```
schedule() 调度循环核心路径：

schedule()
    │
    ├─ 检查 GC STW 标记 → 如果需要，停止当前 M
    │
    ├─ 每 61 次调度检查一次全局队列（防止饥饿）
    │   └─ globrunqget(pp, 1) → 从全局队列取一批 G
    │
    ├─ 从 P 的本地队列取 G
    │   └─ runqget(pp) → 从本地队列头部弹出
    │
    ├─ 本地队列为空 → findRunnable()（核心窃取逻辑）
    │   ├─ 再检查本地队列
    │   ├─ 检查全局队列
    │   ├─ 检查 netpoll（网络 I/O 就绪的 G）
    │   ├─ 随机尝试从其他 P 窃取（work stealing）
    │   │   └─ 从目标 P 的本地队列尾部偷走一半
    │   └─ 都没有 → 当前 M 休眠（stopm）
    │
    └─ execute(gp) → 执行选中的 G
```

### 1.2 内存分配器（runtime/malloc.go）
- TCMalloc 派生的多级分配架构：
```
┌─────────────────────────────────────────────┐
│  mcache（per-P 缓存，无锁分配）              │
│  ├── tiny allocator（< 16B 无指针对象）       │
│  └── alloc[numSpanClasses] → mspan           │
├─────────────────────────────────────────────┤
│  mcentral（每个 size class 的中心缓存）       │
│  └── spanSet（partial / full）               │
├─────────────────────────────────────────────┤
│  mheap（堆管理，向 OS 申请内存）              │
│  ├── pages（基数树管理页面映射）              │
│  └── arenas（64MB 对齐的内存区域）            │
└─────────────────────────────────────────────┘
```

### 1.3 栈管理
- 初始栈大小 2KB（_StackMin）
- 栈增长：morestack → newstack → 分配 2 倍大小的新栈 → 拷贝
- 栈缩减：GC 扫描阶段检查，缩至使用量的 2 倍（最小 2KB）
- 栈拷贝时的指针调整机制

## 2. GC（垃圾回收）深度剖析

### 2.1 三色标记并发 GC
```
                  ┌──────────┐
   新分配对象 ──▶ │  白色     │ ──扫描完成──▶ 回收
                  │（未访问） │
                  └────┬─────┘
                       │ 被引用发现
                       ▼
                  ┌──────────┐
                  │  灰色     │ ──待扫描──▶ 扫描其引用
                  │（已发现） │
                  └────┬─────┘
                       │ 引用扫描完成
                       ▼
                  ┌──────────┐
                  │  黑色     │ ──存活──▶ 保留
                  │（已扫描） │
                  └──────────┘

写屏障（Write Barrier）：
  混合写屏障（Hybrid Write Barrier）确保并发标记的正确性
  - shade(ptr)：新指针指向的对象标记为灰色
  - shade(slot)：被覆盖的旧指针指向的对象也标记为灰色
```

### 2.2 GC 阶段详解
```
    ─── Sweep ───|── Mark Setup ──|──── Concurrent Mark ────|── Mark Term ──|── Sweep ───
                 │  STW（短暂）    │ 与用户代码并发执行        │  STW（短暂）   │
                 │  开启写屏障     │ 后台 Mark Worker          │  关闭写屏障   │
                 │                │ 辅助标记（Assist Mark）    │              │
```

### 2.3 GC 调优参数
- GOGC（默认 100）：控制 GC 触发频率
  - GOGC=100 → 堆增长到上次 GC 后存活量的 2 倍时触发
  - GOGC=off → 禁用 GC（特殊场景）
- GOMEMLIMIT（Go 1.19+）：内存软上限
  - 与 GOGC 协同工作，防止 OOM
  - 适合容器环境的内存管理
- runtime/debug.SetGCPercent / SetMemoryLimit

### 2.4 GC 诊断工具
- GODEBUG=gctrace=1：GC 日志分析
- runtime.ReadMemStats：程序化获取 GC 指标
- go tool trace：可视化 GC 活动时间线
- pprof allocs / heap profile 对比

## 3. 性能调优方法论

### 3.1 性能分析工具链
```
                ┌──────────────────┐
                │  性能问题发现      │
                └────────┬─────────┘
                         │
         ┌───────────────┼───────────────┐
         │               │               │
    ┌────▼─────┐  ┌─────▼──────┐  ┌────▼─────┐
    │ CPU Profile│  │Heap Profile│  │  Trace    │
    │ pprof cpu  │  │pprof heap  │  │go tool    │
    │ 找热点函数  │  │找分配热点   │  │trace      │
    └────┬─────┘  └─────┬──────┘  │找调度延迟  │
         │               │        └────┬─────┘
         ▼               ▼             ▼
    火焰图分析      逃逸分析       goroutine 时间线
    优化热点路径    减少堆分配      优化并发模式
```

### 3.2 常见优化手段（按收益排序）
1. **算法优化**：选择正确的数据结构和算法
2. **减少内存分配**：
   - sync.Pool 对象复用
   - 预分配 slice/map 容量
   - 避免 string ↔ []byte 不必要转换
   - 使用 strings.Builder 代替 string 拼接
3. **减少锁竞争**：
   - 分片锁（Sharded Lock）
   - 原子操作替代互斥锁
   - 无锁数据结构（lock-free queue）
4. **I/O 优化**：
   - 批量操作替代逐条操作
   - 缓冲 I/O（bufio）
   - 连接池复用
5. **编译器提示**：
   - //go:inline / //go:noescape
   - 接口方法去虚拟化

### 3.3 Benchmark 最佳实践
- testing.B 的正确使用（b.ResetTimer / b.ReportAllocs）
- benchstat 统计显著性检验
- 避免编译器优化消除（使用全局变量 sink）
- 子基准测试与表驱动基准测试

## 4. 分布式系统设计

### 4.1 一致性与共识
```
CAP 定理在实践中的取舍：

┌─────────────────────────────────────┐
│              CAP                      │
│         ┌───────────┐                │
│    C ◀──┤           ├──▶ A           │
│ 一致性   │  只能三选二  │  可用性       │
│         └─────┬─────┘                │
│               │                      │
│               ▼                      │
│              P（分区容忍性，必须保证）  │
│                                      │
│  CP 系统：etcd, ZooKeeper            │
│  AP 系统：Cassandra, DynamoDB        │
│  实际选择：大多数场景选择最终一致性     │
└─────────────────────────────────────┘
```

## 5. 混沌工程

### 5.1 混沌工程原则
```
稳态假设 ──▶ 引入故障变量 ──▶ 观察系统行为 ──▶ 验证假设
                │
    ┌───────────┼───────────┐
    │           │           │
  网络故障     进程故障     资源故障
  延迟注入     OOM Kill    CPU 饱和
  分区模拟     异常退出     磁盘满
  DNS 故障     信号中断     I/O 延迟
```

### 5.2 Go 应用的混沌测试

  - 上游服务超时
  - 数据库连接断开
  - 消息队列不可达

### 5.3 韧性验证
