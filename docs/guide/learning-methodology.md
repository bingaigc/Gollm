## 1. 🕐 每日学习节奏

> 核心公式：**学习理论（20%）→ 动手写码（60%）→ 复盘改进（20%）**

### 📊 时间分配

```
┌──────────────────────────────────────────────────────────┐
│                每日 4 小时学习分配                          │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  Phase 1: 📖 学习理论（20% ≈ 50分钟）                     │
│  ┌────────────────────────────────────┐                  │
│  │ • 阅读当天主题的文档和讲解           │                  │
│  │ • 理解核心概念和底层原理             │                  │
│  │ • 看代码示例，但先不急着写           │                  │
│  │ • 在脑中建立架构图                  │                  │
│  └────────────────────────────────────┘                  │
│                                                          │
│  Phase 2: 💻 动手写码（60% ≈ 2.5小时）                    │
│  ┌────────────────────────────────────────────────┐      │
│  │ • 按照任务清单逐一完成编码任务                   │      │
│  │ • 从 L1 入门版开始，逐步升级到 L2、L3           │      │
│  │ • 遇到问题先自己思考 10 分钟再查资料             │      │
│  │ • 每完成一个任务就运行测试                       │      │
│  │ • 使用 go vet、go race detector 检查代码        │      │
│  └────────────────────────────────────────────────┘      │
│                                                          │
│  Phase 3: 📝 复盘改进（20% ≈ 50分钟）                     │
│  ┌────────────────────────────────────┐                  │
│  │ • 整理学习笔记和代码注释             │                  │
│  │ • 提交代码到 Git 仓库               │                  │
│  │ • 写下今天的收获和疑问              │                  │
│  │ • 预习明天的主题                    │                  │
│  └────────────────────────────────────┘                  │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### ⏰ 推荐时间安排

| 时段 | 活动 | 说明 |
|------|------|------|
| 前 50 分钟 | 📖 理论学习 | 精力最充沛时学习新概念 |
| 中间 2.5 小时 | 💻 编码实践 | 进入心流状态，专注写码 |
| 最后 50 分钟 | 📝 复盘总结 | 趁记忆新鲜整理笔记 |

### 🎯 Phase 1 详解：学习理论（20%）

**做什么**：
- 阅读当天主题对应的讲解文档
- 重点理解 [八大模块](./eight-modules.md) 中的前 4 个模块（架构视角、逐行拆解、知识点深挖、执行流模拟）
- 在脑中或纸上画出架构图

**不要做什么**：
- ❌ 不要在理论阶段就打开 IDE 写代码
- ❌ 不要花太多时间在细枝末节上
- ❌ 不要只看不想，要主动思考"为什么这样设计"

**验收标准**：
- ✅ 能用自己的话解释今天的核心概念
- ✅ 能画出大致的架构图或数据流图
- ✅ 知道今天的编码任务大致要怎么做

### 🎯 Phase 2 详解：动手写码（60%）

**做什么**：
- 打开 IDE，按任务清单逐一完成
- 遵循三级代码进化路径：L1 → L2 → L3
- 频繁运行和测试代码
- 使用 Go 工具链检查代码质量

**编码流程**：

```
开始任务
  │
  ├→ 1. 先写 L1 入门版（能跑就行）
  │     └→ 运行验证 ✓
  │
  ├→ 2. 升级到 L2 进阶版（加错误处理）
  │     └→ 运行验证 + go vet ✓
  │
  ├→ 3. 挑战 L3 生产版（完整功能）
  │     └→ 运行验证 + go vet + race detector ✓
  │
  └→ 4. 编写测试用例
        └→ go test -v -race ✓
```

**效率技巧**：
- 🔥 使用 `go run` 快速运行验证
- 🔥 使用 `go test -run TestXxx` 只运行相关测试
- 🔥 使用 `go build -race` 开启竞态检测
- 🔥 遇到报错先看错误信息，80% 的问题答案在错误信息中

### 🎯 Phase 3 详解：复盘改进（20%）

**做什么**：
- 整理代码，添加必要的注释
- 将代码提交到 Git 仓库（详见第 4 节）
- 用一句话总结今天最重要的收获
- 记录遗留的问题和疑惑
- 花 5-10 分钟预览明天的主题

**复盘模板**：

```markdown
## Day X 复盘

### 📅 日期：YYYY-MM-DD
### 📌 主题：XXX

### ✅ 今日完成
- [ ] 任务 1
- [ ] 任务 2
- [ ] 任务 3

### 💡 核心收获（一句话）
> 

### ❓ 遗留疑问


### 🔗 明日预习


### 📊 自评分数：___ / 10
```

## 2. 🤖 如何使用 Prompt 系统

> Prompt 系统是你的 AI 学习助手。正确使用它可以极大提升学习效率。

### 📋 Prompt 使用流程

```
Step 1: 选择当天的主题 Prompt
  │
  ▼
Step 2: 将 Prompt 发送给 AI（如 ChatGPT、Claude）
  │
  ▼
Step 3: AI 按照八大模块为你生成详细讲解
  │
  ▼
Step 4: 按照讲解内容学习和实践
  │
  ▼
Step 5: 遇到不懂的追问 AI
  │
  ▼
Step 6: 完成互动练习和挑战任务
```

### 🎯 Prompt 的正确使用方式

**✅ 好的用法**：

```
📌 "请按照八大模块的格式，详细讲解 Go 的 Channel 机制，
    包括逐行代码分析、执行流模拟和生产环境的坑。"

📌 "我在 Day 4 的 Context 主题上卡住了，
    请帮我用动态执行流模拟的方式解释 Context 的取消传播。"

📌 "请给我一个 Worker Pool 的三级代码进化示例，
    从 L1 到 L3 逐步升级。"
```

**❌ 不好的用法**：

```
❌ "帮我写一个 gRPC 服务"（太模糊，没有指定模块）

❌ "给我所有的代码"（应该自己动手写，AI 辅助理解）

❌ "这个代码有什么问题"（应该先自己分析，带着假设去问）
```

### 💡 追问技巧

当 AI 的回答不够深入时，使用以下追问模板：

| 场景 | 追问模板 |
|------|----------|
| 想深入底层 | "这个特性在 Go runtime 中是如何实现的？" |
| 想看更多示例 | "请给我一个生产环境中使用这个特性的真实案例" |
| 想理解设计决策 | "为什么 Go 要这样设计？和其他方案相比有什么优势？" |
| 想实践验证 | "请给我一个练习题来验证我对这个概念的理解" |
| 想对比学习 | "这个概念和 Java/Python 中的 XXX 有什么区别？" |

### 🔄 迭代学习法

```
第一遍：快速浏览，建立整体印象
    │
    ▼
第二遍：逐行分析，深入理解细节
    │
    ▼
第三遍：动手实践，写代码验证
    │
    ▼
第四遍：总结回顾，查缺补漏
```

## 3. 🆘 遇到卡点怎么办

> 卡住是学习过程中最正常不过的事。关键是有一套系统的方法来快速突破。

### 🔧 五步排障法

```
┌─────────────────────────────────────────────────────────┐
│                    遇到问题了？                           │
│                        │                                │
│                        ▼                                │
│  Step 1: 🔍 仔细阅读错误信息（2分钟）                     │
│  │  80% 的问题答案都在错误信息中                           │
│  │                                                      │
│  ├── 解决了 ✅ → 继续                                    │
│  │                                                      │
│  ▼                                                      │
│  Step 2: 🧠 自己思考和分析（10分钟）                      │
│  │  画出执行流程图，定位问题出在哪一步                      │
│  │                                                      │
│  ├── 解决了 ✅ → 继续                                    │
│  │                                                      │
│  ▼                                                      │
│  Step 3: 📚 查阅官方文档（10分钟）                        │
│  │  Go 官方文档是最权威的参考                              │
│  │  https://pkg.go.dev                                  │
│  │                                                      │
│  ├── 解决了 ✅ → 继续                                    │
│  │                                                      │
│  ▼                                                      │
│  Step 4: 🤖 向 AI 提问（5分钟）                          │
│  │  带着你的分析和假设去提问                               │
│  │  "我遇到了 XXX 问题，我认为原因是 YYY，对吗？"          │
│  │                                                      │
│  ├── 解决了 ✅ → 继续                                    │
│  │                                                      │
│  ▼                                                      │
│  Step 5: 🔄 简化问题（15分钟）                            │
│  │  把复杂代码简化为最小可复现的示例                        │
│  │  一步步排除变量，找到真正的原因                          │
│  │                                                      │
│  └── 解决了 ✅ → 继续                                    │
│                                                         │
│  ⚠️ 如果以上步骤都没解决:                                 │
│  → 记录问题，跳过这个任务，继续下一个                       │
│  → 第二天回来看，很可能豁然开朗                            │
└─────────────────────────────────────────────────────────┘
```

### 🎯 常见卡点类型和应对

| 卡点类型 | 表现 | 应对策略 |
|----------|------|----------|
| 🔴 编译错误 | 代码无法编译 | 仔细看错误信息，通常是语法错误或类型不匹配 |
| 🟡 运行时错误 | panic 或异常退出 | 使用 `recover` 捕获 panic，加 `defer` 打印堆栈 |
| 🔵 逻辑错误 | 结果不符合预期 | 加 `fmt.Println` 打印中间状态，或使用 delve 调试 |
| 🟣 并发错误 | 数据竞争或死锁 | 使用 `-race` 检测竞态，用 `go tool trace` 分析调度 |
| ⚫ 概念不理解 | 看不懂原理 | 回到八大模块的"知识点深挖"和"执行流模拟" |
| 🟤 环境问题 | 工具安装失败 | 检查版本兼容性，使用 Docker 隔离环境 |

### 💡 调试工具箱

```bash
# 编译检查
go build ./...
go vet ./...

# 竞态检测
go run -race main.go
go test -race ./...

# 性能分析
go test -bench . -benchmem
go tool pprof cpu.prof

# 执行追踪
go test -trace trace.out
go tool trace trace.out

# 调试器
dlv debug main.go
```

### ⏱️ "番茄钟"抗卡策略

当你发现自己在一个问题上卡了超过 30 分钟，使用番茄钟策略：

1. ⏸️ **暂停** - 离开屏幕，喝杯水
2. 📝 **记录** - 把问题和你已经尝试的方法写下来
3. 🔀 **切换** - 做下一个任务或看看其他主题
4. 🔄 **回来** - 休息后回来，往往会有新思路

> 🧠 **科学依据**：大脑在休息时会进行"背景处理"（diffuse mode），很多灵感都是在放松时出现的。

## 4. 💎 每日提交代码的黄金建议

> **代码不提交 = 没有写过。** 每日提交代码是最重要的学习习惯之一。

### 🏆 为什么每天都要提交代码

```
✦ 建立可追溯的学习轨迹
  → 30 天后你可以回顾自己的进步曲线

✦ 养成专业开发者的工作习惯
  → 企业中每天提交代码是基本要求

✦ 防止代码丢失
  → 本地文件可能丢失，Git 仓库是最好的备份

✦ GitHub 贡献图变绿
  → 连续 30 天的绿色贡献图是最好的简历名片

✦ 方便回顾和对比
  → 可以 diff 不同版本，看到自己的进化
```

### 📋 每日提交规范

**提交信息格式**：

```
Day{N}: {主题} - {简要描述}

例如:
Day1: goroutine - 实现基础并发程序和泄漏检测
Day5: sync - 实现线程安全缓存，对比 Mutex 和 Channel 性能
Day10: gRPC - 实现一元调用服务，添加认证拦截器
Day22: Docker - 多阶段构建，镜像优化至 8MB
```

**提交频率**：

| 时机 | 说明 |
|------|------|
| 完成每个任务后 | 小步提交，每个任务一个 commit |
| 发现好的实现后 | 及时保存好的代码版本 |
| 离开电脑前 | 确保当天进度已保存 |
| 修复 Bug 后 | 记录问题和修复方案 |

**仓库目录建议**：

```
my-go-learning/
├── day01-goroutine/
│   ├── basic/
│   │   └── main.go
│   ├── leak-detect/
│   │   └── main.go
│   └── README.md
├── day02-channel/
│   ├── buffered/
│   │   └── main.go
│   ├── producer-consumer/
│   │   └── main.go
│   └── README.md
├── ...
├── day30-final-project/
│   ├── cmd/
│   ├── internal/
│   ├── Dockerfile
│   ├── k8s/
│   └── README.md
└── README.md  ← 总览文档
```
